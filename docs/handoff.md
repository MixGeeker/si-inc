## 2026-11-17 交接 · 当前日制原型

接手以当前工作区代码为准。在仓库根目录运行 `npm run dev`，从「日期与菜单 → 新建对局」进入原型。本文顶部说明当前事实和剩余工作；后面的分支、提交、旧周制和到期方案均为历史记录。[场景入口](game-architecture.md) · [事件与状态规范](game-runtime.md) · [玩法提案](gameplay-design.md)

### 现在能运行的内容

- **单阵营日制对局。** 从 GPT、Claude、Grok 和六个起始大洲中各选一个。每局持有独立 `runId`、规则版本与种子，开局是已完成 0 天、18 token 和 32 语料。每天结算研究，每 2 天结算经营 token；尚无独立电脑对手或完整市场扩散。[对局状态与日结算](../packages/game/run.ts)
- **4 秒/天，1/2/5×，暂停独立。** 倍速只保存正值，手动暂停保留所选速度；菜单、研究、正式决策、开发面板和后台等暂停来源叠加，关闭其中一项不会解除其他暂停。恢复沿用当前日剩余时间，后台不补算；前台迟到最多追赶 3 天，遇决策或结局停止。**没有固定到期日或固定局长**，持续时间由局势与玩家的选择决定。[时钟适配器](../apps/web/src/scenes/clock.ts) · [暂停原因](../apps/web/src/scenes/store.ts)
- **研究与叙事已接通。** 三页共 50 项科技、7 个研究槽、10 种流派选择；工期、固定语料、事件资格和后续报道均按日计算。新闻可按总览、当前条目或今日浏览；四条普通决策与一条自主编程事件已接入，正式选择只结算一次。普通新闻浏览不暂停，正式决策窗暂停。[研究规则](../packages/game/research.ts) · [叙事事件](narrative-events.md)
- **实际结束边界。** 危险研究或决策使 Project HUMAN 进度达到 100% 时自动进入人类胜利结算；玩家也可在菜单确认主动结束。目前尚无多阵营评分、合成人排名或自动 AI 胜利结算。其他胜利条件与评分方式需要玩法规则继续确定，不能从旧到期提案推定。[结局检查](../packages/game/run.ts)
- **地图与调试。** 六个大洲共用经营入口与地理归属，已有算力标记和人口图层；这些展示不代表已经可以建站、转投、改造或召回。开发面板支持独立调试副本、单步日结算、推进到下个事件及发放 token。[地图场景](../apps/web/src/scenes/world/WorldScene.tsx)
- **回放与保存边界。** 可导出日制 `ReplayV2` 或 `version: 2` 调试回放，记录规则、`runId`、种子和按日指令；当前不提供旧周制回放迁移。时钟有日内进度 checkpoint 接口，但尚无完整对局存读档界面，也没有离线收益。[回放格式](../packages/game/types.ts) · [回放与时间线](../packages/game/inspection.ts)

### 剩余工作与玩法决定

1. **接通真实经营。** 明确各国初始人口、每日新增和转投、共享空槽与建设卡、多阵营余额及电脑行动；使用同一日初快照处理竞争申请。地图现有标记、科技条件试算与人口预览都不能代替这些业务结算。
2. **接通两幕行动。** 合成人计划、逐日改造、迁移补贴、监管召回、退役人口与自动永昼转永夜仍是玩法提案。需要人口守恒、预算和行动拒绝路径的共同验收。[两幕提案](gameplay-design.md#两幕玩法状态机)
3. **统一胜利与评估。** 保留当前 HUMAN 到 100% 的真实结算边界，其他胜利条件由玩法规则明确后实现。现役人数、经营收益等只作为阶段评估或主动结束摘要的候选指标，不设置固定日期强制排名，也不使用固定天数的总 token 预算。
4. **校准持续经营的节奏。** 按首次研究、首国达标、扩张与巩固等实际阶段比较大小国开局；研究归一化、吞吐、人口语料与行动费用仍需平衡。时长由模拟进展与玩家结束决定，不预设固定局长。
5. **实现完整存读档。** 确定运行快照与日内 checkpoint 的协调保存、加载和版本校验，补存读档界面；当前回放导出和时钟 checkpoint 不能等同于完整保存功能。

### 接手后的当前验收

1. 新建对局应显示第 0 天；1×、2×、5×分别约 4、2、0.8 秒一天。暂停时换速只修改所选倍速，开关菜单和研究后仍保持手动暂停；没有其他暂停原因时才恢复。

3. 无胜负触发时可持续超过旧固定期限，后续报道仍在约定日期投递。玩家主动结束显示本局最终快照。
4. 未来经营接通后再验收多阵营竞争、人口守恒与建站等提案；当前不能把这些目标算例当作已通过的功能。修改公共状态或事件语义时，在根目录运行 `npm test` 和 `npm run build`。[全仓约定](../AGENTS.md)

### 现在能跑到哪一步

周制原型可以从 GPT、Claude、Grok 中选一家和一个起始市场。每局只有这家阵营的一份余额。常速 4 秒一周，偶数周发收入，竞争消息和突变按种子排期，正式突变只扣款一次。第 120 周自动超时。市场扩散、独立电脑对手、反制研发和自动胜负还缺结算，技能面板展示的仍是周制价格。当前有回放格式，尚无对局存读档。[对局状态与周推进](../packages/game/run.ts) · [回放格式](../packages/game/types.ts)

### 新版已明确的玩法

- **两幕按阵营推进。** 玩家与电脑在同一天竞争。第一幕争取会转投的普通沉浸用户，用语料研究、再争取更多用户。一个国家的**所有阵营合计**覆盖 100% 人口，便向各家开放当地的合成人计划。阵营首次主动启用才进入第二幕，只能改造自己的普通用户。合成人锁定原阵营，现役时每天提供 3 份语料，普通用户提供 1 份。
- **两种货币。** `token` 付行动和建设，语料付研究。花掉语料只动研究余额，飞轮记录实际日产量。普通用户和现役合成人各占一个服务名额。
- **数据中心按国建。** 发源国开局开放全部建设额度，仍受国家容量限制。海外看**本阵营普通沉浸人口占该国人口的比例**，到 25%、50%、75% 分别开放约三分之一、三分之二、全部额度。各家共用实际空槽。中国 8 槽、美国 5 槽、日本 2 槽。国家门槛与 6 个市场的经营奖励分别计算。[建设与经营规则](gameplay-design.md#发源国与海外槽位)

### 接手后的第一组验收

1. 建一局固定种子的日本算例，给 GPT 60%、Claude 40% 的普通沉浸人口。日本达到 100% 时两家都可启用当地计划，两家都暂缓时全图保持永昼。其他未达标国家继续争夺沉浸用户。
